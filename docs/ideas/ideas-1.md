# 아이디어 후보 — Cycle 1 (Run #1)

> mission.md §2(탐색 범위), §3(제약 조건) 안에서 브레인스토밍한 후보 8개.
> 이 시점의 점수는 **경쟁 제품 조사 이전의 가설**이다 (외부 근거 없음). research/validate 단계에서 재평가한다.
> 평가 기준(각 1~5점, mission.md §4): Pain / Gap / Feasibility / Demonstrability / Differentiation. 합계 18점 이상 & Feasibility ≥ 4 만 통과.

## 후보 목록

### 1. 요리용 멀티 타이머 (라벨 붙는 동시 타이머)
한 번에 여러 요리를 할 때 "면 8분", "국 15분"처럼 이름 붙인 타이머를 동시에 여러 개 돌리고, 끝나면 각각 알림.
- Pain 3 — 폰 기본 타이머는 대부분 1개만 크게 보여주고 라벨이 약함. 여러 개 돌리다 헷갈리는 경험은 흔하지만 "심각한" 고통은 아님.
- Gap 4 — 기본 타이머 앱(iOS Clock)은 멀티 타이머 라벨링이 불편함. 틈새가 명확해 보임 (가설).
- Feasibility 5 — 순수 로컬 상태 + `setInterval`/타임스탬프 계산 + `expo-notifications` 로컬 알림. 서버·유료 API 불필요.
- Demonstrability 5 — Expo Go에서 타이머 여러 개 생성하고 실제로 울리는 걸 바로 확인 가능.
- Differentiation 3 — "라벨 + 동시 다중 + 프리셋 저장"이 조합되면 차별점이 될 수 있으나 유사 앱이 이미 많을 가능성 있음 (가설, research 필요).
- **합계: 20**

### 2. 커스텀 인터벌 운동 타이머 (타바타/필라테스 시퀀스 빌더)
"준비 10초 → 운동 40초 → 휴식 20초 × 8라운드" 같은 시퀀스를 직접 만들고 저장해서 반복 실행. 구간마다 소리/음성으로 안내.
- Pain 4 — 홈트레이닝 하는 사람에게 반복적으로 필요한 도구이고, 기존 앱은 광고/유료 시퀀스 제한이 많다는 불만이 흔함 (가설, research에서 리뷰 확인 필요).
- Gap 3 — 유사 앱(Tabata Timer 류)이 다수 존재. 빈틈은 "무료 + 시퀀스 무제한 저장 + 광고 없음" 정도.
- Feasibility 5 — `expo-av`/`expo-speech`로 로컬 사운드·음성 안내 가능. 서버 불필요.
- Demonstrability 5 — 실제 인터벌 진행을 폰에서 눈/귀로 바로 확인 가능.
- Differentiation 3 — 조합형 차별점, 강력하지는 않음.
- **합계: 20**

### 3. 더치페이 정산기 (오프라인, 1회성 모임 정산)
회원가입/계좌연동 없이, 모임 후 "누가 얼마 냈고 누구에게 얼마씩 보내면 되는지"만 그 자리에서 계산. 계산 후 앱에 저장 안 해도 됨.
- Pain 3 — 흔한 상황이지만 대부분 암산이나 계산기 앱으로 대충 해결하고 있어 "강한" 고통은 아님.
- Gap 3 — Splitwise 등은 계정·동기화가 필요해 1회성 모임엔 무거움. "가입 없이 1회용"이 빈틈 (가설).
- Feasibility 5 — 순수 계산 로직, 저장도 선택적. 매우 단순.
- Demonstrability 5 — 즉시 결과 확인 가능.
- Differentiation 3 — 가입 없는 단순함이 차별점이 될 수 있으나, 강한 락인 요소가 없어 "왜 계속 씀"이 약함.
- **합계: 19**

### 4. 레시피 인분/단위 변환기 + 나만의 레시피 저장
레시피를 저장해두고 인원수를 바꾸면 재료량이 자동 환산됨 (컵/큰술 등 한국식 계량 단위 포함).
- Pain 3, Gap 3, Feasibility 4, Demonstrability 4, Differentiation 3
- 계량 단위 데이터(컵→g 변환 등 재료별 밀도)를 정확히 넣으려면 손이 많이 갈 수 있음 (Feasibility 리스크).
- **합계: 17** — 기준 미달 (18 미만)

### 5. 약/영양제 복용 리마인더 + 로그
정해진 시간에 로컬 알림, 복용 체크 시 스트릭 기록.
- Pain 4, Gap 2, Feasibility 3, Demonstrability 4, Differentiation 2
- Feasibility 리스크: Expo Go에서 로컬 예약 알림의 백그라운드 안정성이 불확실함 (가설 — 검증 필요, 아이폰 종료/재부팅 시 재예약 로직 필요).
- **합계: 15** — 기준 미달

## 왜 틀렸을 수 있는가 (자기 반박, 근거 없이 낙관하지 않기 위해)
- 세 후보 모두 "Gap"과 "Differentiation" 점수가 실제 경쟁 앱을 하나도 찾아보지 않은 상태의 추측이다. 앱스토어에 이미 동일한 조합(예: 라벨형 멀티 타이머)이 흔하다면 Gap/Diff 점수가 크게 낮아져야 한다.
- Pain 점수도 실제 사용자 리뷰의 불만("이 부분이 불편해서 못 씀")을 확인하지 않은 추정치다.
- 세 후보 모두 "한 번 쓰고 안 쓸 수 있는" 유틸리티형이라 재방문(리텐션) 요소가 약하다는 공통 리스크가 있다 — research/validate에서 반드시 짚어야 함.
